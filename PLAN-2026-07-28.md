Before any technical content: the core transport work is **closed to outside contribution**.

On #1011 (SEP-2575), maintainer @Kehrlann wrote on 2026-07-10 that SEP-2575 is "tightly linked to #1004" (MRTR), is foundational, and "the core team [will] drive this … we are not accepting contributions for this at the moment" — restated on 2026-08-03 when @elang2 offered a scoped server-side PR, and on 2026-08-06: "it won't land before September." So the plan has two tracks with different rules:

- **Track A — contributable now, 2.x minor.** Non-breaking, board-tracked items where maintainers are actively reviewing.
- **Track B — core-team-owned, 3.x.** Stateless core, MRTR, era dispatch. Our role is design input via PR #1089 and issue comments, plus readiness work in our own codebase, not SDK PRs.

An outside plan that ignores this will produce PRs that get closed.

## 2. Spec facts the plan must respect (corrections from draft 1)

- `_meta` keys are namespaced: `io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientCapabilities` (changelog). Not bare `protocolVersion` / `capabilities`.
- SEP-2567: cross-call state uses **server-minted handles passed as ordinary tool arguments**. There is no `_meta.stateHandle` and no server-side handle store. The first draft's `StateHandleStore` reintroduced a session store; drop it.
- MRTR: every result carries required `resultType`, values `"complete"` | `"input_required"`. Clients MUST treat a missing `resultType` from an older server as `"complete"`. `input_required` results carry opaque `requestState`; the client retries the same request with `inputResponses`. No `"success"`/`"failure"`.
- SEP-2243: `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` MUST mirror the body and servers MUST reject mismatches — this is a spec MUST on the modern path, but (per Kehrlann on #994) rejecting *absent* headers from legacy clients must not be the default on a dual-era server.
- SSE resumability (`Last-Event-ID`) is removed; a broken stream means re-issuing the request. This is the argument for the Tasks extension on long-running calls.
- Tasks extension (SEP-2663): polling `tasks/get` replaces blocking `tasks/result`; `tasks/update` added; `tasks/list` **removed**; servers may return a task handle unsolicited.
- Deprecated with ≥12-month window: Roots, Sampling, Logging, HTTP+SSE transport, Dynamic Client Registration.
- Per PR #1089 (not independently verified by me): `subscriptions/listen` replaces GET + `resources/subscribe`; `ping`, `logging/setLevel`, `notifications/roots/list_changed` removed; new error codes -32020/-32021/-32022; `notifications/message` MUST NOT be emitted unless request `_meta` carries `io.modelcontextprotocol/logLevel`. **[unverified — confirm against spec before relying on it]**

## 4. Backward compatibility

Two questions, and they are separate:

**Wire level — dual-era server.** The spec permits a server to select behaviour from how the client opens: `initialize` → legacy session path; `server/discover` or a request carrying `_meta` + `MCP-Protocol-Version: 2026-07-28` with no session → modern path. PR #1089's D1 puts this dispatch at the transport front door rather than as a flag on session types. Python and Cloudflare ship dual-era on one endpoint; Go/TypeScript make the new revision an explicit transport opt-in. For Spring Boot / Tomcat deployments behind reverse proxies, one endpoint serving both is the lower-friction default. Recommend dual-era default, with a builder switch to run modern-only. This is #1089's open question 2 — raise it there rather than on #1011.

**API level — 2.x vs 3.x.** Maintainers have already signalled 3.x for breaking changes. What is breaking:
- `resultType` as a real record component on ~15 result records (#1089 D4; Jackson serialises components, so an interface default won't hit the wire). Under the repo's CONTRIBUTING "Case B" record rules this is a break.
- Removing `initialize()`, `McpServerSession`, `McpStreamableServerSession`, `LifecycleInitializer`, GET-stream resumability.
- SEP-2164 error code change (confirmed breaking by maintainer).

What is not: `extensions` map, `ttlMs`/`cacheScope`, `@Deprecated` annotations, outbound header emission, `server/discover` as an additive method, auth SEPs.

`callTool()` keeps returning `CallToolResult` — #1089 D3 resolves MRTR inside the client session layer with a bounded retry loop that invokes the *existing* sampling/elicitation/roots handlers. That is the right call and preserves Spring AI's tool-calling integration; the first draft's `callToolMultiRoundTrip` overload is unnecessary.

## 6. Conformance — definition of done

The repo currently validates against `@modelcontextprotocol/conformance` **0.1.15** (README; dependabot #814 bumped it from 0.1.11). The Rust Tier-1 assessment (issue #3179 in the spec repo, 2026-08-21) used server 67/67 and client 50/50 as the bar. Commands, using the existing repo layout:

```
# server
./mvnw compile -pl conformance-tests/server-servlet -am exec:java
npx @modelcontextprotocol/conformance@0.1.15 server --url http://localhost:8080/mcp --suite active --spec-version 2026-07-28

# client
./mvnw clean package -DskipTests -pl conformance-tests/client-jdk-http-client -am
npx @modelcontextprotocol/conformance@0.1.15 client --spec-version 2026-07-28 \
  --command "java -jar conformance-tests/client-jdk-http-client/target/<jar>"
```

Scenario names for the 2026-07-28 suite are whatever `--list` returns; the first draft's `tools_call_mrtr` etc. were invented. Check the suite version actually carrying 2026-07-28 scenarios before quoting a number — 0.1.15 predates the final spec.

## 7. Risks and open questions

- **Maintainer bandwidth is the critical path**, not engineering. One core maintainer is visible on every thread. Nothing in Track B moves until the Spring AI team starts it; "September" is the only date on record.
- **Design fragmentation.** #1089 is uncommented; three SEP-2243 PRs overlap; session-store PRs (#914, #1048, #500) pull the other way. Without a maintainer statement on #1089, contributors will keep filing partial PRs that get closed.
- **Reactor shape for MRTR.** Handlers must not hold a suspended `Mono` across HTTP round trips; state must round-trip via `requestState`. D3 handles the client; the server SPI shape is undecided.
- **Jackson 2 vs 3 for `_meta`.** Both JSON modules must deserialise namespaced `_meta` keys identically; route through `McpJsonMapper` with a `TypeRef<Map<String,Object>>`.
- **Spring AI coupling.** Not checked in this plan; someone must grep `spring-ai`'s MCP module for `McpServerSession`, `initialize`, and sampling usage before 3.x is scoped.
